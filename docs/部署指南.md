# CF-Server-Monitor 部署指南

这份文档面向第一次部署的用户。按步骤做完以后，你会得到一个部署在 Cloudflare Workers 上的服务器监控面板，并可以在 VPS 上安装探针，把 CPU、内存、磁盘、网络速度、月度流量和套餐进度上报到面板。

## 1. 部署前准备

你需要准备：

- 一个 GitHub 账号
- 一个 Cloudflare 账号
- 至少一台 VPS
- 一个已经 fork 的项目仓库

本项目部署到 Cloudflare Workers，数据存在 Cloudflare D1。VPS 只需要执行面板生成的安装命令，不需要安装数据库。

## 2. Fork 项目

打开项目仓库，点击右上角 `Fork`，把项目 fork 到自己的 GitHub 账号下。

fork 后，你后续的修改和 GitHub Actions 部署都会发生在自己的仓库里。

## 3. 创建 Cloudflare API Token

进入 Cloudflare 控制台：

1. 点击右上角头像
2. 进入 `My Profile`
3. 打开 `API Tokens`
4. 点击 `Create Token`
5. 可以使用 `Edit Cloudflare Workers` 模板，或者创建自定义 Token

Token 至少需要能部署 Workers、读取账号信息、使用 D1。最简单的做法是给当前账号下 Workers/D1 相关权限。

创建完成后复制 Token，后面会填到 GitHub Secrets 的 `CF_API_TOKEN`。

## 4. 获取 Cloudflare Account ID

进入 Cloudflare 控制台首页，选择你的账号，在右侧或账号概览里可以看到 `Account ID`。

复制它，后面会填到 GitHub Secrets 的 `CF_ACCOUNT_ID`。

## 5. 创建 D1 数据库

进入 Cloudflare 控制台：

1. 打开 `Workers & Pages`
2. 进入 `D1 SQL Database`
3. 点击创建数据库
4. 数据库名建议使用：

```txt
server-monitor-db
```

创建后进入数据库详情页，复制 `Database ID`。

后面会填到 GitHub Secrets 的 `D1_DATABASE_ID`。

## 6. 配置 GitHub Secrets

进入你 fork 后的 GitHub 仓库：

1. 打开 `Settings`
2. 进入 `Secrets and variables`
3. 选择 `Actions`
4. 点击 `New repository secret`

需要添加这些 Secret：

| Secret 名称 | 作用 |
|---|---|
| `CF_API_TOKEN` | Cloudflare API Token，用于 GitHub Actions 部署 Worker |
| `CF_ACCOUNT_ID` | Cloudflare Account ID |
| `D1_DATABASE_ID` | Cloudflare D1 Database ID |
| `API_SECRET` | VPS 探针上报密钥，也可作为默认管理员密码 |
| `API_USER_NAME` | 管理员用户名，可选，建议填写 |

`API_SECRET` 建议使用足够长的随机字符串，不要用简单密码。这个值同时用于 VPS 探针上报认证，泄露后别人可能伪造上报。

## 7. 触发部署

Secrets 配好后，进入 GitHub 仓库：

1. 打开 `Actions`
2. 找到 `Deploy to Cloudflare Workers`
3. 点击 `Run workflow`

或者你推送一次代码到 `main` 分支，也会自动触发部署。

部署成功后，Actions 日志里会显示部署完成。Cloudflare Workers 里也能看到名为：

```txt
cf-server-monitor
```

的 Worker。

## 8. 打开面板

进入 Cloudflare Workers，打开 `cf-server-monitor` 的访问地址。

后台地址是：

```txt
https://你的-worker域名/admin
```

登录信息：

- 用户名：`API_USER_NAME`，未设置时默认为 `admin`
- 密码：`API_SECRET`

如果没有设置 `API_USER_NAME`，系统会使用默认逻辑，建议部署时明确设置。

## 9. 首次升级数据库

第一次部署后，进入后台：

1. 登录 `/admin`
2. 打开 `Database Management`
3. 点击 `Upgrade Database`

这个步骤会把当前版本需要的字段补齐，比如流量校准、流量统计模式、统计网卡等字段。

以后项目更新后，如果更新说明里提到新增数据库字段，也需要再点一次 `Upgrade Database`。

注意：不要随便点 `Rebuild Database`。它会重建数据库并清空服务器和历史数据。

## 10. 添加服务器

进入后台 `Servers` 页面：

1. 输入服务器名称
2. 选择或填写分组
3. 点击 `ADD SERVER`

添加后，服务器列表里会出现安装命令。

## 11. 安装 VPS 探针

在服务器列表中点击复制安装命令，然后登录你的 VPS，以 root 权限执行。

Linux 常见系统使用：

```sh
curl -sL https://你的-worker域名/install.sh | bash -s install -id=服务器ID -secret='你的API_SECRET' -url=https://你的-worker域名/update -interval=60 -ping=http -reset_day=1
```

Alpine Linux 使用后台弹窗里的 `Alpine Linux` 目标系统，会生成：

```sh
curl -sL https://你的-worker域名/install-alpine.sh | sh -s install ...
```

安装完成后，探针会作为服务在 VPS 上运行，并定时上报数据。

常用管理命令：

```sh
systemctl status cf-probe
journalctl -u cf-probe -f
systemctl restart cf-probe
systemctl stop cf-probe
```

Alpine 或无 systemd 环境，请以安装完成后输出的管理命令为准。

## 12. 更新项目后的操作

项目更新后通常分两类：

### 只更新前端或 Worker

等待 GitHub Actions 部署完成即可。

### 更新了数据库字段

部署完成后进入后台，点击：

```txt
Database Management -> Upgrade Database
```

### 更新了探针脚本

如果更新内容涉及 `install.sh`、`install-alpine.sh`、流量统计、启动时间、探针参数等，需要重新复制安装命令到 VPS 执行。

重新执行安装命令是覆盖更新，不会一直累积垃圾。脚本会停止旧服务、覆盖探针脚本、覆盖服务配置并重新启动。

会保留的正常数据：

- `/var/lib/cf-probe/traffic.dat`：本机月度流量累计状态
- 系统日志：systemd journal 或 Alpine 日志

如果更新内容涉及流量统计，重新安装探针后建议按 `使用指南.md` 里的流程重新校准一次 `Panel Used`。

## 13. 卸载探针

后台提供卸载命令，也可以手动执行：

```sh
curl -sL https://你的-worker域名/install.sh | bash -s uninstall
```

Alpine：

```sh
curl -sL https://你的-worker域名/install-alpine.sh | sh -s uninstall
```

卸载会删除探针服务、脚本和本地流量追踪数据。

## 14. 常见部署问题

### Actions 部署失败

优先检查：

- `CF_API_TOKEN` 是否正确
- `CF_ACCOUNT_ID` 是否正确
- `D1_DATABASE_ID` 是否正确
- Cloudflare Token 是否有 Workers/D1 权限

### 后台无法登录

检查：

- `API_USER_NAME` 是否是你输入的用户名
- `API_SECRET` 是否是你输入的密码
- GitHub Actions 是否已经重新部署成功

### 添加服务器后一直离线

检查：

- VPS 是否执行了安装命令
- 安装命令里的 `-url=` 是否是当前 Worker 地址
- 安装命令里的 `-secret=` 是否等于 GitHub Secret 里的 `API_SECRET`
- VPS 是否能访问 Cloudflare Worker

可以查看探针日志：

```sh
journalctl -u cf-probe -n 50
```

### 更新后新字段不显示或保存失败

进入后台执行：

```txt
Database Management -> Upgrade Database
```
