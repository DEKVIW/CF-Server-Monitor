# CF-Server-Monitor 使用指南

这份文档说明后台各参数怎么填、流量进度如何校准、如何在 VPS 上查看真实网卡和流量。目标是让面板里的套餐流量进度尽量接近 VPS 服务商后台。

## 1. 面板能做什么

部署完成并安装探针后，面板可以查看：

- CPU 使用率
- 内存使用率
- 磁盘使用率
- 实时上下行速度
- 月度上下行流量
- 套餐流量使用进度
- Ping 延迟
- 服务器在线/离线状态
- 历史图表

其中流量相关有几类数据：

| 名称 | 含义 |
|---|---|
| `NET` | 当前实时网络速度 |
| `TRF` | 总接收/发送流量 |
| `MTRF` | 当前账单周期内探针累计的月流量 |
| `USE` | 套餐流量使用进度，也就是和 VPS 后台最接近的那个进度 |

## 2. 后台服务器参数说明

进入 `/admin`，点击服务器的编辑按钮，可以配置这些字段。

### Server Name

服务器名称，只影响显示。

示例：

```txt
RackNerd LA
Bandwagon US
```

### Group Name

服务器分组，只影响后台和首页展示。

示例：

```txt
US VPS
HK VPS
Production
```

### Price

价格备注，只影响显示。

示例：

```txt
$40/Y
```

### Expiration Date

到期时间，只影响显示和到期提醒样式。

### Bandwidth

带宽备注，只影响显示。

示例：

```txt
1Gbps
500Mbps
```

### Traffic Limit

套餐流量上限。这个字段会参与套餐流量进度计算。

示例：

```txt
500GB
1TB
15.5TB
```

建议按 VPS 后台显示的套餐总量填写。如果后台写 `15.63 TB`，这里可以填 `15.63TB`。

### Traffic Mode

套餐流量统计模式。

| 模式 | 含义 | 适合情况 |
|---|---|---|
| `RX+TX` | 入站 + 出站双向统计 | 搬瓦工、RackNerd 这类常见双向计费 VPS |
| `RX` | 只统计入站 |
| `TX` | 只统计出站 |

大多数 VPS 套餐流量是双向统计，也就是入站和出站都算。你不确定时，先选 `RX+TX`，然后观察一两天和 VPS 后台是否接近。

### Traffic Reset Day

流量重置日，也就是服务商每月几号重置流量。

示例：

```txt
1
15
```

如果服务商后台每月 15 号重置，就填 `15`。

探针会按这个日期计算当前周期的 `MTRF` 和周期起点。校准 `Panel Used` 时，系统会记录当前周期起点；后续如果周期起点变化，就会自动忽略旧的 `Panel Used`，避免旧周期数据影响新周期。

### Panel Used

VPS 服务商后台当前已用流量。这个字段用于校准套餐进度。

示例：

```txt
261.5GB
10.68GB
88.08GB
```

保存时，系统会记录当前探针的 `MTRF` 作为基线。后续计算方式是：

```txt
套餐进度 = Panel Used + 保存之后探针新增的流量
```

举例：

保存时：

```txt
VPS 后台已用：261.5GB
探针当前 MTRF：20GB
```

几天后：

```txt
探针当前 MTRF：30GB
探针新增：30GB - 20GB = 10GB
项目显示：261.5GB + 10GB = 271.5GB
```

所以 `Panel Used` 不是一直累加旧值，而是作为校准起点。

### Traffic NIC

流量统计网卡。这个字段是可选的。

不填时，探针会自动选择：

```txt
手动指定网卡
-> IPv4 默认出口网卡
-> eth/en/wl/venet 这类常见公网网卡
-> 排除 Docker/隧道/虚拟网卡后的剩余网卡
-> 全量兜底
```

大多数 VPS 不填也能自动选到正确网卡。

如果你已经确认公网网卡是 `eth0`，建议填写：

```txt
eth0
```

多个网卡可以用英文逗号分隔：

```txt
eth0,ens3
```

不过大多数 VPS 只需要一个公网主网卡。不要填写 `docker0`、`br-*`、`veth*`、`warp`、`he-ipv6`、`ipv6net` 这类虚拟或隧道网卡，否则容易重复统计。

### Report Interval

探针上报间隔，单位秒。

推荐：

```txt
60
```

如果服务器很多，可以适当调大，比如 `120` 或 `180`，减轻 Worker 和 D1 压力。

### Ping Mode

Ping 探测方式。

| 模式 | 说明 |
|---|---|
| `HTTP` | 默认模式，兼容性较好 |
| `TCP` | TCP 连接探测，不兼容时切回 HTTP |

## 3. 推荐的流量校准流程

为了让套餐进度更接近 VPS 后台，建议按这个流程做：

1. 部署最新代码
2. 后台执行 `Upgrade Database`
3. 编辑服务器，填好 `Traffic Limit`、`Traffic Mode`、`Traffic Reset Day`
4. `Traffic NIC` 可以先不填；如果你确认是 `eth0`，就填 `eth0`
5. 保存后复制新的安装命令
6. 到 VPS 上重新执行安装命令
7. 等探针上报一两次
8. 打开 VPS 服务商后台，查看当前已用流量
9. 回到项目后台，把 `Panel Used` 填成服务商后台当前已用流量
10. 保存

之后项目会按校准后的起点加新增流量，长期偏差会明显小于之前全网卡统计的方式。

## 4. 为什么项目流量可能和 VPS 后台不一致

常见原因：

### 1. Docker 网络被重复统计

如果把 `/proc/net/dev` 里的所有网卡都加起来，会把这些也算进去：

```txt
docker0
br-xxxx
vethxxxx
```

Docker 服务多时，这些虚拟网卡会让项目统计比 VPS 后台跑得更快。

当前探针已经默认排除这些网卡。

### 2. IPv6 隧道或 WARP 被重复统计

常见接口：

```txt
sit0
he-ipv6
ipv6net
warp
wg0
tailscale0
```

这些流量底层可能还是经过 `eth0` 出去。如果同时统计隧道网卡和 `eth0`，就可能重复。

当前探针默认不把它们计入自动统计。

### 3. 服务商后台有延迟

有些 VPS 后台不是实时刷新，可能延迟几分钟到几小时。

### 4. GB 和 GiB 单位差异

项目内部按 1024 进制换算。部分服务商后台可能按 1000 进制显示，数字会有小差异。

### 5. 单向/双向计费不同

如果服务商只算出站，而你选择了 `RX+TX`，项目会偏快。
如果服务商双向计费，而你只选了 `TX`，项目会偏慢。

搬瓦工、RackNerd 常见套餐一般按双向流量理解，建议先选 `RX+TX`。

## 5. 在 VPS 上查看网卡

查看所有网卡：

```sh
ip -o link show | awk -F': ' '{print $2}'
```

示例输出：

```txt
lo
eth0
docker0
br-7060846d3974
veth89ef549@if10
sit0@NONE
ipv6net@NONE
```

或者

```
ip route get 1.1.1.1 | awk '{for(i=1;i<=NF;i++) if($i=="dev"){print $(i+1); exit}}'
```

一般应该选择 `eth0`、`ens3`、`enp1s0` 这类公网主网卡。

不要选：

```txt
lo
docker0
br-*
veth*
sit0
he-ipv6
ipv6net
warp
wg0
tailscale0
```

## 6. 查看默认出口网卡

查看 IPv4 默认出口网卡：

```sh
ip route get 1.1.1.1 | awk '{for(i=1;i<=NF;i++) if($i=="dev"){print $(i+1); exit}}'
```

如果输出：

```txt
eth0
```

那 `Traffic NIC` 可以填：

```txt
eth0
```

查看 IPv6 默认出口网卡：

```sh
ip -6 route get 2606:4700:4700::1111 | awk '{for(i=1;i<=NF;i++) if($i=="dev"){print $(i+1); exit}}'
```

如果输出是 `ipv6net`、`he-ipv6`、`warp` 这类隧道或虚拟网卡，通常不要把它和 `eth0` 一起统计，否则可能重复。

如果提示：

```txt
RTNETLINK answers: Network is unreachable
```

说明当前机器没有可用 IPv6 默认路由，不影响 IPv4 统计。

## 7. 查看每个网卡的当前流量

在 VPS 上执行：

```sh
awk 'NR>2{gsub(":","",$1); printf "%-16s RX %.2f GB  TX %.2f GB\n",$1,$2/1024/1024/1024,$10/1024/1024/1024}' /proc/net/dev
```

示例：

```txt
lo               RX 0.10 GB  TX 0.10 GB
eth0             RX 9.61 GB  TX 9.71 GB
docker0          RX 2.00 GB  TX 2.10 GB
br-xxxx          RX 1.20 GB  TX 1.30 GB
vethxxxx         RX 5.00 GB  TX 5.10 GB
```

如果 Docker/veth/br 的流量很多，而项目又把它们算进去了，就会比 VPS 后台偏快。当前新探针默认会排除它们。

## 8. 查看当前探针本地月流量文件

探针会把本机月度累计状态保存到：

```txt
/var/lib/cf-probe/traffic.dat
```

查看：

```sh
cat /var/lib/cf-probe/traffic.dat
```

常见内容：

```txt
RX_PREV=...
TX_PREV=...
RX_PERIOD=...
TX_PERIOD=...
LAST_CHECK=...
PERIOD_START=...
```

含义：

| 字段 | 说明 |
|---|---|
| `RX_PREV` | 上次记录的网卡接收总字节 |
| `TX_PREV` | 上次记录的网卡发送总字节 |
| `RX_PERIOD` | 当前周期累计接收流量 |
| `TX_PERIOD` | 当前周期累计发送流量 |
| `LAST_CHECK` | 上次检查时间 |
| `PERIOD_START` | 当前流量周期开始时间 |

正常使用不需要手动改这个文件。

## 9. 手动计算当前系统网卡流量

只看 `eth0` 的 RX/TX：

```sh
awk '$1=="eth0:"{printf "RX %.2f GB\nTX %.2f GB\n",$2/1024/1024/1024,$10/1024/1024/1024}' /proc/net/dev
```

如果你的公网网卡是 `ens3`，把 `eth0` 改成 `ens3`：

```sh
awk '$1=="ens3:"{printf "RX %.2f GB\nTX %.2f GB\n",$2/1024/1024/1024,$10/1024/1024/1024}' /proc/net/dev
```

查看双向合计：

```sh
awk '$1=="eth0:"{printf "SUM %.2f GB\n",($2+$10)/1024/1024/1024}' /proc/net/dev
```

这只是网卡累计值，不等于本月套餐已用，因为系统网卡计数通常从开机或网卡初始化后累计。项目的 `MTRF` 是按重置日和增量计算的。

## 10. 什么时候需要重新校准 Panel Used

这些情况建议重新校准：

- 刚安装探针
- 刚更新了流量统计逻辑
- 刚设置或修改了 `Traffic NIC`
- VPS 后台刚重置流量
- 项目显示和 VPS 后台差距明显

校准方法：

1. 等探针正常上报
2. 打开 VPS 服务商后台
3. 看当前已用流量
4. 在项目后台编辑服务器
5. 把 `Panel Used` 填成服务商后台当前已用
6. 保存

保存后，后续进度会从这个点继续加新增流量。

## 11. 推荐配置示例

### 搬瓦工 / RackNerd 常见配置

```txt
Traffic Limit: 按后台套餐填写，例如 500GB 或 15.63TB
Traffic Mode: RX+TX
Traffic Reset Day: 按后台重置日填写，例如 1 或 15
Traffic NIC: eth0
Panel Used: 当前 VPS 后台已用流量，例如 10.68GB
Report Interval: 60
Ping Mode: HTTP
```

如果不想填 `Traffic NIC`，也可以留空。新探针会优先自动选择 IPv4 默认出口网卡，你的常见 VPS 场景通常也是 `eth0`。

### Docker 服务很多的机器

建议明确填写：

```txt
Traffic NIC: eth0
```

这样不会把 Docker bridge、veth、容器内部转发流量重复算进去。

### 有 WARP 或 IPv6 隧道的机器

常见网卡：

```txt
warp
he-ipv6
ipv6net
sit0
```

默认不要把这些填进 `Traffic NIC`。多数情况下它们底层仍经过公网主网卡，重复统计会偏高。

## 12. 安装命令参数说明

后台复制出来的安装命令大致包含这些参数：

```sh
-id=服务器ID
-secret=API_SECRET
-url=https://你的-worker域名/update
-interval=60
-ping=http
-reset_day=1
-iface=eth0
```

参数说明：

| 参数 | 说明 |
|---|---|
| `-id` | 服务器 ID，后台添加服务器后自动生成 |
| `-secret` | 上报密钥，必须等于 GitHub Secret 里的 `API_SECRET` |
| `-url` | 上报地址，一般是 Worker 地址加 `/update` |
| `-interval` | 上报间隔，单位秒 |
| `-ping` | Ping 模式，`http` 或 `tcp` |
| `-reset_day` | 每月流量重置日 |
| `-iface` | 可选，指定统计网卡，例如 `eth0` |

不填 `-iface` 时，探针自动选择网卡。

## 13. 常见问题

### 不填 Traffic NIC 可以吗？

可以。探针会优先读取 IPv4 默认出口网卡：

```sh
ip route get 1.1.1.1
```

如果结果是 `eth0`，就会统计 `eth0`。

如果你已经确认公网网卡就是 `eth0`，填写 `eth0` 会更明确、更稳定。

### 填错 Traffic NIC 会不会显示 0？

不会直接显示 0。探针会检查指定网卡是否存在，不存在就回退自动模式。

### 为什么校准后还会有小误差？

正常。可能来自：

- 服务商后台延迟
- GB/GiB 换算差异
- 服务商统计规则不同
- 面板四舍五入

目标是避免长期运行后误差越来越大，尤其避免 Docker/隧道网卡导致几天差好几个 GB。

### VPS 后台重置后，Panel Used 会自动变 0 吗？

你不需要每次手动把 `Panel Used` 改成 0。
新版探针会上报当前周期起点。只要周期起点变化，系统就会认为进入新周期，并自动忽略旧 `Panel Used`，用当前周期的探针流量重新算。老探针没有周期起点时，才会退回到“当前 `MTRF` 小于校准基线”的兼容判断。

### 重新执行安装命令会产生垃圾吗？

不会。重新安装会停止旧服务、覆盖脚本和服务配置，再重新启动。

会保留 `/var/lib/cf-probe/traffic.dat`，这是正常的月度流量状态文件。

### 项目比 VPS 后台跑得快怎么办？

按顺序检查：

1. `Traffic Mode` 是否选错，双向还是单向
2. `Traffic NIC` 是否为空或填了正确公网网卡
3. VPS 是否有 Docker、WARP、IPv6 隧道
4. 是否已经重新安装新探针
5. 是否重新校准过 `Panel Used`

常用排查命令：

```sh
ip -o link show | awk -F': ' '{print $2}'
ip route get 1.1.1.1 | awk '{for(i=1;i<=NF;i++) if($i=="dev"){print $(i+1); exit}}'
awk 'NR>2{gsub(":","",$1); printf "%-16s RX %.2f GB  TX %.2f GB\n",$1,$2/1024/1024/1024,$10/1024/1024/1024}' /proc/net/dev
```
